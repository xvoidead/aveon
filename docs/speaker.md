# колонка (экспериментально)

Треки авеона можно играть на Яндекс Станции Лайт 2. В плеере есть кнопка колонки (правее эквалайзера), настройки в разделе «Колонка» (Настройки → «Остров и окна»). Нажал один раз — режим включён: всё, что играешь в Авеоне, идёт на колонку, а на компьютере тишина. Нажал снова — звук возвращается на компьютер. Трек кончился на колонке — включается следующий из очереди. Точка на кнопке: зелёная — колонка на связи, красная — нет. Если колонка не заиграла, режим выключается и трек играет на компьютере. Пауза в этом режиме останавливает колонку, а «играть» начинает трек сначала. Код: `renderer/speaker.js`, `src/speaker.js`.

## как устроено

```
авеон на компьютере ── resolveStream ──► локальный сервер 127.0.0.1:<порт>
                                              ▲
                  обратный SSH-туннель  ◄─────┘
                          ▼
колонка: 127.0.0.1:19790 ◄── maind --gst-launch (uridecodebin → alsasink)
```

Колонка не умеет TLS (в прошивке нет glib-networking) и не достаёт до аудио-CDN SoundCloud, поэтому поток отдаёт компьютер: HLS-плейлисты переписываются на его адрес, обычные потоки идут с `Range`, файлы из кэша и свои файлы тоже. Правило брандмауэра не нужно: колонка ходит на свой `127.0.0.1`, а туннель приводит её к серверу на компьютере. Управление (запуск плеера, громкость, стоп) идёт по SSH скриптами из `src/speaker-core.js`.

## включить

0. Настройки → «Остров и окна» → «Колонка» → включить «Играть на колонке» (по умолчанию выключено).
1. С компьютера должно работать `ssh <имя>` на колонку без пароля (ключ, `BatchMode`). Колонка с рутом и dropbear на 22 порту.
2. Записать имя в настройки (синхронизироваться между компьютерами они не будут):

```js
await tishe.config.set({ speaker: { enabled: true, host: 'lite2', level: 0.7 } })
```

`host` — имя из `~/.ssh/config` или адрес, пусто — выключено. `level` — громкость колонки на время музыки, 0…1 (Master 0…255; 0.7 это 179, с 0.85 уже слишком громко). Прежняя громкость возвращается сама.

## пробовать

Из консоли окна (`npm run dev` открывает её):

```js
const r = await tishe.source.search('sc', 'слезы сатоши королевский')
await tishe.speaker.play(r[0])     // играет на колонке
await tishe.speaker.status()       // { configured, playing, track }
await tishe.speaker.stop()
```

Работает с любым треком, который умеет проиграть сам плеер: поток сервиса, кэш, локальный файл. Играет один трек, новый заменяет прежний. Очереди нет: трек кончился, колонка замолчала.

## чего пока нет

- компьютер должен быть включён и авеон запущен: поток идёт через него;
- нет перемотки и настоящей паузы, полоса времени в окне на колонке не двигается; громкость колонки задаётся в настройках, ползунок Авеона на неё не действует; режим выключается при перезапуске;
- голосом («Алиса, включи…») не управляется, это отдельная часть;
- проверено в настоящем Electron (`--tester --dev`, консоль окна): трек SoundCloud играет на колонке. Трек из Яндекс Музыки и из кэша авеона вживую не гонялись.

## чем опасно для самой колонки

`maind --gst-launch` на любой сигнал (INT, HUP, TERM) выходит, не закрыв звук как положено, и оставляет в системе общую память и семафор микшера dmix (ключи `0x400`, `0x401`, смотреть `ipcs -a`). Следующий клиент цепляется к ним, устройство «готовится», а запуск потока до железа не доходит: молчит и плеер, и **сама Алиса**, пока не перезапустить quasar. Конец трека он переживает чисто, сирот нет.

Поэтому скрипты колонки после выхода плеера, при запуске и при остановке вызывают `dmix_clean`: он удаляет эти объекты, только если к памяти никто не подключён (`nattch = 0`). Если делаете свои скрипты с `gst-launch`, делайте так же. Починка вручную: `q stop`, `ipcrm -M 0x400 -M 0x401 -S 0x400`, `q start`.
