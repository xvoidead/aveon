# Конструктор своего дизайна

Дата: 2026-09-29
Статус: черновик, ждёт проверки

## Зачем

Каждый юзер может собрать свой дизайн плеера целиком, не зная ни HTML, ни CSS. Он выбирает часть плеера (кликом по самому плееру или из списка) и настраивает ей цвет, фон, форму, размер, тень, шрифт, видимость и место внутри блока. Готовый дизайн стоит рядом с «Бочкой», «Формой», «Дзеном» и «Стеклом», ездит между устройствами через аккаунт, и его можно отправить другу кодом.

### Что считаем успехом

- Юзер без знания кода за несколько минут делает дизайн, который заметно отличается от готовых, и видит каждое изменение сразу, на живом плеере.
- Код дизайна от другого человека никогда не ломает плеер и ничего не грузит из сети, даже если его подделали руками.
- После обновления плеера старые дизайны продолжают работать. Если какая-то часть исчезла, её настройки просто тихо пропускаются.
- Работает на компьютере и на телефоне.

### Не делаем сейчас

- Общую галерею дизайнов на сервере (возможно, вторым этапом).
- Свободное перетаскивание блоков по окну и поле для своего CSS.
- Правку отдельных окон: острова, мини-плеера, режима «во весь экран». Меняется только главное окно.

## Как это устроено

Используем подход «каталог частей». В коде есть список частей плеера. Для каждой части указаны её элемент в разметке и какие свойства у неё можно менять. В дизайне хранятся только значения свойств. CSS из них собирает сам плеер, строго по каталогу, и ни одна строка из дизайна не попадает в CSS как есть.

### Файлы

| Файл | Что делает |
|---|---|
| `renderer/design-core.js` (новый) | Чистая логика без DOM: каталог частей и свойств, проверка и очистка дизайна (`cleanDesign`), сборка CSS (`designCss`), коды `AVD1.` (`designCode`, `readDesignCode`). Подключается обычным `<script>` и через `module.exports` для тестов в Node. |
| `renderer/designer.js` (новый) | Редактор: боковая панель, выбор части кликом, список частей, черновик и живое превью, сохранение. |
| `renderer/look.js` | Применение активного дизайна в `applyLook`, карточки «Мои дизайны» в разделе «Дизайн», вставка кода `AVD1.` в «Вставить код», «Сбросить всё» больше не удаляет дизайны. |
| `renderer/styles.css` | Стили панели редактора, подсветки при выборе части и карточек дизайнов. |
| `renderer/mobile.css` | Панель на телефоне открывается снизу, на 60 % высоты. |
| `renderer/index.html` | Подключение двух новых скриптов перед `look.js`. |
| `scripts/design-core.test.js` (новый) | Тесты `node --test` для `design-core.js`. |

Сервер и синхронизацию не трогаем: дизайны лежат в `config.look` и уже ездят через аккаунт (`src/account.js → syncedSettings`).

## Данные

```js
config.look.designs = [{
  id: 'k3j9x2',              // случайная строка, [a-z0-9]{4,12}
  name: 'Ночной неон',       // до 40 символов
  base: 'barrel',            // barrel | form | zen | glass — раскладка и стиль, на которых строится дизайн
  palette: { oak: '#101018', amber: '#ff3da6' },  // только заданные цвета, остальные — из основы
  accentFromCover: true,     // акцент берётся из обложки, даже если в palette задан amber (тогда amber — запасной)
  fonts: { display: 'jost', text: '' },           // ключи FONTS; пусто — как в основе
  radius: 100,               // общий множитель скруглений, %, 0…250
  parts: { cover: { radius: 30, shadow: 'glow' }, play: { fill: { kind: 'solid', a: 'accent' } } },
  order: { stage: ['cover', 'title', 'artist', 'seek', 'controls'] },  // только те, что двигали
}];
config.look.skin = 'd:k3j9x2';  // активный дизайн; готовые — как раньше, 'glass' и т. д.
```

Ограничения: до 30 дизайнов, код одного дизайна до 32 КБ.

`palette` — те же переменные, что уже есть в плеере, но без `--`: `oak` (фон окна), `oak-2` (сцена), `rivet` / `rivet-2` (поверхности), `hoop-dim` / `hoop` (линии и обручи), `text` / `text-2` / `text-3`, `amber` (акцент), `voice` (голоса и бочка), `danger`.

## Каталог частей

У каждой части есть `id`, русское название, группа, CSS-селектор, список свойств и, при необходимости, маппинг свойства в CSS для этой части. Например, «размер» у обложки — это `width`, а у названия — `font-size`.

**Сцена** (группа `stage`, порядок можно менять):
шапка «авеон», обложка, обручи, спектр, надпись «в бочке», название трека, артист, «слушать вместе», перемотка (дорожка, заливка, время), кнопки управления, кнопка «играть», громкость и кнопки под ней, звонок Discord, аккаунт.

**Библиотека** (группа `library`, порядок можно менять):
вкладки (обычная и выбранная), поиск, полка плейлистов, заголовок раздела, строка трека (обычная, при наведении, играющая), обложка в строке, название в строке, артист в строке, длительность.

**Окно**: фон сцены, фон библиотеки, разделитель между ними.

Точный список селекторов проверяется в каждой из четырёх основ во время реализации. Если в какой-то основе части нет (например, обручей у «Стекла»), в списке она показывается серой с подписью «нет в этой основе».

## Свойства

| Свойство | Что юзер видит | Значение | Проверка |
|---|---|---|---|
| `color` | Цвет текста / значка | `#rrggbb` или токен: `accent`, `voice`, `text`, `text-2`, `text-3`, `bg` | regex или белый список токенов |
| `fill` | Фон: нет / цвет / градиент | `{ kind: 'none'|'solid'|'gradient', a, b, angle }` | цвета как выше, угол 0…360 |
| `opacity` | Прозрачность фона | 0…100 | clamp |
| `radius` | Скругление | 0…100 (100 — круг или таблетка) | clamp |
| `size` | Размер | 50…200 % | clamp |
| `font` | Шрифт | ключ `FONTS` или пусто | белый список |
| `weight` | Толщина | 300 / 400 / 500 / 600 / 700 / 800 | белый список |
| `align` | Выравнивание | left / center / right | белый список |
| `caps` | Заглавными | true / false | boolean |
| `shadow` | Тень | none / soft / strong / glow (свечение акцентом) | белый список, готовые пресеты |
| `border` | Рамка | `{ w: 0…4, c: цвет }` | clamp и цвет |
| `hidden` | Скрыть | true / false | boolean |

Токены цветов превращаются в `var(--amber)` и т. п. Поэтому дизайн может использовать цвет из обложки, если юзер так хочет.

`cleanDesign(raw)` возвращает новый объект только с известными частями, свойствами и допустимыми значениями. Всё остальное отбрасывается молча. Функция вызывается на каждом входе: при загрузке из конфига, при вставке кода, при каждом изменении в редакторе.

## Сборка CSS

`designCss(design)` выдаёт текст для одного `<style id="look-design">` в конце `<head>`:

- Каждое правило начинается с `html.skin-design:not(#_)`. Специфичность выходит на уровне id, поэтому правила перебивают стили основ (`html.skin-form .row` и т. п.) без `!important`, а инлайн-стили от скриптов (анимации, `--m`, скретч) остаются главнее.
- Значения берутся только из очищенного дизайна и подставляются по маппингу каталога.
- `hidden` → `display: none`. Порядок → `order: N` для частей группы: сцена и библиотека во всех основах — колонки flex.
- Палитра, акцент, шрифты и скругления идут через уже существующий путь `applyLook` (переменные на `:root`, `applyRadius`). На `<html>` ставятся классы `skin-<основа>` и `skin-design`.

Если в дизайне заданы цвета фона, палитра из обложки фон больше не перекрашивает (`SKIN_FIXED`), как у «Дзена». Если `accentFromCover` выключен и задан `amber`, акцент фиксированный (`SKIN_ACCENT`).

## Редактор

### Где открывается

«Настройки → Оформление → Дизайн». Под готовыми дизайнами идёт строка «Мои дизайны»: карточки с макетом в цветах дизайна и карточка «+ Создать дизайн». Клик по карточке включает дизайн. Кнопка «⋯» на карточке открывает меню: «Изменить», «Копия», «Скопировать код», «Удалить».

Новый дизайн создаётся из того, что сейчас на экране: основа — текущий дизайн, остальное пусто. Если сейчас включён свой дизайн, берётся его копия.

### Панель

Когда редактор открыт, окно настроек прячется. Справа появляется панель шириной 360 px, а слева видно живой плеер, который и служит превью. На телефоне панель выезжает снизу на 60 % высоты.

- **Шапка:** поле с названием, кнопка «Выбрать на плеере» (прицел), кнопка «Закрыть».
- **Вкладка «Общее»:** основа (4 кнопки), палитра (12 цветов, у каждого «×» — вернуть как в основе), «Акцент из обложки», шрифты заголовков и текста, общие скругления.
- **Вкладка «Части»:** дерево «Окно / Сцена / Библиотека». У каждой части есть глазик (скрыть или показать) и стрелки ↑↓ (порядок внутри группы). Клик по части открывает её свойства: собственные контролы, у каждого свойства «×», внизу — «Сбросить часть».
- **Низ:** «Отмена» и «Сохранить».

### Выбор кликом

Кнопка-прицел включает режим выбора. При наведении на плеер часть под курсором обводится рамкой акцентного цвета, рядом появляется её название. Ищется самая вложенная часть из каталога через `closest` по селекторам. Клик перехватывается на фазе захвата (`preventDefault` и `stopPropagation`): плеер не реагирует, а панель переходит к свойствам этой части. Esc или повторное нажатие на прицел выключает режим. Скрытую часть кликом не выбрать, для неё есть список.

### Черновик и превью

Редактор работает с черновиком. `applyLook` берёт черновик вместо сохранённого дизайна, пока он открыт, и CSS пересобирается на каждое изменение. Для ползунков — не чаще раза в кадр.

- «Сохранить»: черновик записывается в `look.designs`, дизайн становится активным, конфиг сохраняется.
- «Отмена», «Закрыть» или Esc: если были изменения, спрашиваем «Выйти без сохранения?». Черновик выбрасывается, всё возвращается как было.

После закрытия снова открываются настройки на разделе «Дизайн».

## Коды и синхронизация

- «Скопировать код»: `AVD1.` + base64 от JSON очищенного дизайна без `id`.
- «Вставить код» в «Оформлении» теперь понимает оба формата. `AVL1.` работает как раньше, это всё оформление целиком. `AVD1.` добавляет дизайн в «Мои дизайны» с новым `id` и включает его. Если имя уже занято, в конец дописывается « 2».
- Если код битый, не читается или больше 32 КБ, показываем «Это не код дизайна» и ничего не меняем.
- Если дизайнов уже 30, показываем «Уже 30 дизайнов — удали какой-нибудь».
- Синхронизация — как у остального `look`, через аккаунт. Отдельной логики нет.

## Ошибки и крайние случаи

- Активный дизайн удалили (или его удалили на другом устройстве) → включается его основа.
- В дизайне неизвестная основа → берётся «Бочка».
- «Сбросить всё» в «Оформлении» сбрасывает остальные настройки, но оставляет дизайны. Текст подтверждения поправим соответственно.
- Пока открыт редактор, настройки с другого устройства синхронизируются в фоне, но черновик не трогают.

## Проверка

**Автотесты** (`node --test scripts/design-core.test.js`):
- `cleanDesign` отбрасывает неизвестные части и свойства, битые цвета (`red; background:url(...)`, `#fff`, `expression(...)`), ограничивает числа по краям и приводит пустой вход к пустому дизайну.
- В `designCss` для дизайна с попыткой подсунуть строки нет ни `url(`, ни `@import`, ни `}`, пришедших из данных. Каждое правило начинается с `html.skin-design:not(#_)`.
- Код дизайна после записи и чтения даёт тот же объект. Слишком большой или битый код отклоняется.

**Вручную** (`npm start`):
- Во всех четырёх основах: выбрать кликом обложку, кнопку «играть», строку трека и вкладки, поменять им свойства, спрятать часть, переставить части в сцене.
- «Отмена» возвращает всё как было, «Сохранить» переживает перезапуск.
- Скопировать код, удалить дизайн, вставить код обратно — дизайн тот же.
- Узкое окно и мобильная раскладка: панель снизу, выбор касанием.
